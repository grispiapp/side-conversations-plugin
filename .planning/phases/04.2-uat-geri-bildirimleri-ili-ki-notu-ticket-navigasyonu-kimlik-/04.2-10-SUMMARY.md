**New Jest test (`environment-static.test.ts`) mechanically enforces environment.ts's zero-template-literal invariant by reading the source from disk, stripping block and leading-`//` comments, and asserting no backtick survives — replacing three doc-comment sentences as the sole enforcement mechanism.**

## Accomplishments
- Added `src/grispi/client/__tests__/environment-static.test.ts` — reads `environment.ts` from disk via `readFileSync(path.join(__dirname, "..", "environment.ts"), "utf8")`, strips block comments then leading-`//` lines, and asserts the stripped text contains no backtick
- Two robustness assertions prevent the gate from silently degrading: the stripped text must still contain `GRISPI_BASE_URLS` (catches a stripper that deletes everything) and all three environment keys `preprod`/`prod`/`prod_tr` (catches a naive `//`-anywhere strip that would eat `https://` inside the URL values)

## Decisions Made
- Comment-stripping order matters and is deliberately two-stage: block comments (`/\*[\s\S]*?\*\//g`, lazy) stripped first, then only lines matching `/^\s*\/\//` (leading `//`) are dropped — never a mid-line `//` strip, which would truncate `GRISPI_BASE_URLS`'s `https://...` URL string values
- Source path resolved with `path.join(__dirname, "..", "environment.ts")` + `readFileSync`, explicitly not `require.resolve` — the plan called this out because `require.resolve` can return a compiled/resolved path instead of the literal `.ts` source on disk
- Stripping logic extracted into a shared `stripComments` helper (used by all four tests via one `strippedSource` computed once in the `describe` block) rather than repeated per-test, per plan's guidance ("Ayıklamayı ayrı bir yardımcı fonksiyona koy ki testler onu paylaşsın")
