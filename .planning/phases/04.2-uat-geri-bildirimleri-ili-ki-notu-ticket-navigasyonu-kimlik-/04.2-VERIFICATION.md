**SC9/UX-09 is half-closed.** Its "the write is always attempted" clause shares the same fix and is closed. Its "the field is verifiably persisted" clause is not — and cannot be — closed by this gap-closure round, because the defect (CR-01) is that the one live-proven write mechanism sits only in a `catch` branch that the happy path never reaches. The team's own probe evidence for the `/v2` PATCH's `fields`-array persistence on this exact endpoint does not exist; RESEARCH.md's P1 probe body carried only `comment`. This was surfaced to the user with full evidence, and the user made an explicit, recorded decision (CONTEXT.md, "Düzeltme — D-22'nin gerekçesindeki hata") to leave the code as written and measure the outcome in live UAT rather than have an unverified fix applied. That is the correct call for a verifier to honor as a human-verification item, not a code gap — but it is also not something this verifier can mark VERIFIED, since no automated evidence proves the field persists on the happy path. `04.2-UAT.md` item 7 already names the residual risk, the silent-failure mode (ticket created, email sent, never findable in listing), and the exact fix (move the `public/v1` fields-only PATCH out of the `catch` and run it unconditionally after the `/v2` PATCH) if UAT surfaces the failure.

**Everything else is an unchanged regression check.** SC2–SC6 pass exactly as they did in the initial verification (files untouched by the gap-closure plans, tests still green in the full 527/527 run). SC7 and SC8 remain routed to human UAT for the same jsdom-cannot-measure-pixels reason as before, unchanged by this round.

**Test-quality debt (WR-03), not a gap:** the D-01 ordering test at `side-conversation-queries.test.tsx:1235-1247` still measures call order (`invocationCallOrder`), which the hoist made tautological — the assertion would pass even if every `await linkAssertion` were deleted.
