# Phase 04.2 Plan 02: Ticket navigation — environment→URL derivation, context threading, presentation components Summary

**`grispiTld`/`buildAgentTicketUrl` derive Grispi agent-UI ticket URLs from the existing `GRISPI_BASE_URLS` map (zero new host literals), `useGrispi().environment`/`agentName` are now populated end-to-end in both plugin and standalone bootstrap paths, and two new presentation components (`TicketKeyLink`, `ParentKeyChip`) render the side-ticket-vs-parent-ticket key distinction — none of it wired into a screen yet.**

## Accomplishments
- `grispiTld(env)` derives the agent-UI TLD from `GRISPI_BASE_URLS` (single source of truth, CORE-04) — no second `{env: host}` map
- `buildAgentTicketUrl(tenantId, env, ticketKey)` builds the full agent-UI ticket URL via string concatenation (never a template literal, preserving `environment.ts`'s existing zero-`${` regression gate), URL-encodes the ticket key, and is documented as an agent-UI deep-link helper only — never a source for API request hosts
- `BootstrapPluginInitDeps` gained two required fields (`setEnvironmentState`, `setAgentName`); `bootstrapPluginInit` now resolves the environment exactly once and feeds both `HttpHandler` (`setEnvironment`) and React state (`setEnvironmentState`) from that single resolution, immediately followed by `setAgentName(bundle.context.agent?.fullName ?? null)` alongside the existing `setAgentEmail` call
- `GrispiContextType` gained `environment: GrispiEnvironment | null` and `agentName: string | null`; both are wired in the standalone branch (from `StandaloneDevConfig`) and the plugin branch (via the new bootstrap deps)
- `DEFAULT_DEV_AGENT_NAME` ("Davut Kember") added to `standalone-dev.ts`, mirroring `DEFAULT_DEV_AGENT_EMAIL`'s existing live-verified-identity pattern; `StandaloneDevConfig.agentName` resolves from `REACT_APP_DEV_AGENT_NAME` (trimmed) with that default fallback
- `TicketKeyLink` — new `<a>` component: purple/monospace, `target="_blank"` + `rel="noopener noreferrer"`, full ticket key as visible text, locked `aria-label`, `aria-hidden` external-link icon, `href` built from `buildAgentTicketUrl`
- `ParentKeyChip` — new `<span>` component: neutral (`bg-muted`/`text-muted-foreground`/`border-border`) pill, two size variants (`default`/`compact`), no interactive attributes of any kind, both the "üst talep" label and the key visible as text (never color-only)

## Decisions Made
- `buildAgentTicketUrl` uses string concatenation, never a template literal — the sole deliberate divergence from RESEARCH.md/PATTERNS.md's sketch code, required to keep `environment.ts`'s zero-`${` gate (T-04.1-01) intact
- `setEnvironmentState`/`setAgentName` are required (non-optional) `BootstrapPluginInitDeps` fields, matching the existing `setEnvironment`/`onEnvironmentReady` convention — a missing call site fails the build, not silently at runtime
- `resolveGrispiEnvironment(...)` is called exactly once per bootstrap; the resulting value is handed to both `setEnvironment` (HttpHandler) and `setEnvironmentState` (React state) rather than resolving twice
- `TicketKeyLink`/`ParentKeyChip` take their three trust-boundary inputs as props rather than calling `useGrispi()` internally — keeps both components pure/provider-free in tests and keeps every caller's data source visible (D-08); screen-level wiring is explicitly out of scope for this plan (Plan 06/07)
