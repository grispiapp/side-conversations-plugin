# Phase 04.2 — UI Design Contract

> Visual and interaction contract for Phase 04.2: UAT geri bildirimleri — ilişki notu, ticket navigasyonu, kimlik netliği ve dar/kısa panel dayanıklılığı. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Converts `04.2-CONTEXT.md`'s 21 locked decisions (D-01..D-21) into pixel/copy/state contracts; does not revisit them.

**Scope:** No new screens. This phase edits four existing surfaces — the chat screen header/status blocks, the conversations-list screen (new blocked state), the reply/compose composer toolbar, and `ThreadMessage`'s identity row — plus adds three small new presentational components (`TicketKeyLink`, `ParentKeyChip`, `InfoBox`, `ParentBanner`) and one compact-viewport token set. Out of scope: any new API capability beyond the internal-note `PATCH` (UX-01, data-layer only, no new UI), attachment/inline-image behavior (Phase 4, unchanged), the local-dev zoom artifact (D-21, explicitly no code change).

**Design system continuity:** palette, base spacing tokens, and the 3–4-role typography scale are carried over verbatim from `03-UI-SPEC.md`/`04-UI-SPEC.md` (both approved). This phase adds **zero new dependencies** (RESEARCH.md "Standard Stack": every surface reuses `@radix-ui/react-icons`, existing `cva`/`cn` primitives, and the codebase's own hand-rolled accessible popover pattern — no Radix Popover, no container-queries plugin). Two new icons enter the icon vocabulary: `ExternalLinkIcon` (already used by `AttachmentChip`'s read-only variant, reused here for `TicketKeyLink`/`ParentBanner`'s CTA) and `InfoCircledIcon` (new this phase, used identically for both `InfoBox` and `ParentBanner` — one icon = one meaning: "informational, not an error/warning").

## Spacing Scale

|---|---:|---|
| xs | 4px | icon/label gaps (`ParentKeyChip` inline gap, `InfoBox` icon-to-text gap) |

### D-19 compact token set — exact values and arithmetic

Four targets, matching D-19's own literal text ("header, panel inset, liste satırı, yanıt editörü min yüksekliği") exactly:

| Token / selector | Normal | Compact (`max-height: 620px`) | Delta |
|---|---:|---:|---:|
| `--panel-header-height` | `3rem` (48px) | `2.5rem` (40px) | **−8px** chrome |
| `--panel-inset` | `1rem` (16px) | `0.75rem` (12px) | horizontal only, 0 height impact (see below) |
| `.side-conversation-row` min-height (new marker class, `conversation-row.tsx`) | `72px` | `56px` | −16px per row (list density, not feed-height-bearing) |
| Reply editor min/max-height (`rich-text-composer.tsx`, `mode="reply"`) | `min-h-24` (96px) / `max-h-40` (160px) | `min-h-16` (64px) / `max-h-28` (112px) | **−32px** chrome (at min-height) |
| Compose editor min-height (`mode="compose"`, discretionary extension of D-19 — see Assumption below) | `min-h-48` (192px) | `min-h-32` (128px) | −64px chrome |

**`--panel-inset` has zero height effect in the chat screen** — `RichTextComposer`'s recipient row and editor both use hardcoded `px-4`/`py-2`/`py-3`, not `var(--panel-inset)`. `--panel-inset` only affects horizontal padding (`conversation-row.tsx`, list-screen wrappers, `ErrorCard`/`EmptyState`) — it is included in the compact set because D-19 names it explicitly and because it doubles as a D-20 narrow-width aid (12px vs 16px side padding reclaims 8px of usable width at ~280px), not because it grows the feed.

**UX-08 arithmetic (measured baseline: total panel ~405px, feed ~197px at 1366×587):**

```
Compact feed gain = (−8px header)  →  feed +8px
                   + (−32px reply-editor min-height)  →  feed +32px
                   ────────────────────────────────────────────
                   = +40px

197px (baseline) + 40px = 237px  =  197px × 1.203  →  ≥20% taller ✓ (exact target)
```

Toolbar row height (48px: `h-8` buttons + `py-2`) and the recipient line (`min-h-9`, 36px) are **unchanged** in compact mode — they are not named by D-19 and are already minimal; shrinking them further would drop the toolbar's own `size="toolbar"` (32px) buttons below their established floor.

Exceptions (unchanged from Phase 2/4, still apply):
- Dropdown row height ~40px, chip pill height 32px (`h-8`), image thumbnail 72px — all carried over verbatim, no compact variant (not named by D-19, not on the critical feed-height path).

## Layout & Component Notes

*(Supplementary section — carried over from Phase 1–4's precedent because this phase's component anatomy, state machines, and exact class strings are load-bearing for planner/executor.)*

### 1. `TicketKeyLink` (D-06, D-07, D-08, D-10 — side-ticket half)

**Anatomy:** `<a>` (native anchor, never `window.open`/`onClick` — matches D-07/D-08's explicit "no imperative popup API" rule already established for `ThreadAttachments`).

```
<a
  href={buildAgentTicketUrl(tenantId, environment, sideKey)}
  target="_blank"
  rel="noopener noreferrer"
  aria-label={`${sideKey} talebini yeni sekmede aç`}
  className="inline-flex h-8 shrink-0 items-center gap-1 whitespace-nowrap rounded-sm
             font-mono text-sm font-semibold text-primary
             underline decoration-primary/40 underline-offset-2
             hover:decoration-primary
             focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2"
>
  {sideKey}
  <ExternalLinkIcon className="size-3 shrink-0" aria-hidden="true" />
</a>
```

- **Hit area:** `h-8` (32px) — matches the toolbar-button/chip-height exception already established in Phase 2 (`size="toolbar"`) and Phase 4 (`AttachmentChip`) for this mouse-first, desktop-iframe surface. Not the generic 40–44px target — a header title link is not a primary action control.
- **Truncation:** `shrink-0` + `whitespace-nowrap` — **the key text is never allowed to truncate** (hard constraint). At 280px width the header row is `back button (40px) + title column (flex-1, min-w-0) + trailing menu (40px)` ≈ 184px available for the title column; the key (≤12 chars, e.g. `TICKET-9999`) plus icon needs ~90px — never contends for space in practice, but the CSS guarantees it structurally even in a theoretical narrower future.
- **Pending state (sideKey still null, envelope not yet resolved):** header title renders plain text `"Yeni konuşma"` (no link, no icon, `text-sm font-semibold text-foreground`) — never an empty/broken link. The instant `PanelNavigationStore.bindCreatedTicket` resolves `sideKey`, the title becomes the live `TicketKeyLink` (existing observer re-render, no new plumbing).
- **`ScreenHeader` is NOT modified** — this is composed entirely at the `chat-screen.tsx` call site via the existing `title`/`subtitle` `ReactNode` props.

### 2. `ParentKeyChip` (D-10 — parent half)

One component, two size variants (mirrors `ConfirmDialog`'s established "one component, prop-driven variants" precedent, Phase 2):

```
function ParentKeyChip({ parentKey, size = "default" }: { parentKey: string; size?: "default" | "compact" }) {
  const compact = size === "compact";
  return (
    <span
      aria-label={`Üst talep: ${parentKey}`}
      className={cn(
        "inline-flex shrink-0 items-center gap-1 rounded-full border border-border bg-muted text-muted-foreground",
        compact ? "px-1 py-0 text-[10px] leading-4" : "px-2 py-0.5 text-xs font-medium"
      )}
    >
      <span>üst talep</span>
      <span className="font-mono text-foreground">{parentKey}</span>
    </span>
  );
}
```

- **Never a link** — plain `<span>`, no `href`, no `tabIndex`, no button semantics, `cursor-default` (implicit, no `cursor-pointer` class applied).
- **Never accent-colored** — `bg-muted`/`text-muted-foreground`/`border-border` only, per D-10's "nötr gri."
- **`default` size** — used standalone inside `ParentBanner` (§3).
- **`compact` size** — used inline inside the chat screen's `ScreenHeader` `subtitle` slot (§1's sibling decision, below).

### 3. Chat header subtitle — parent chip placement (Assumption, auto-mode)

**Assumption:** CONTEXT.md's D-06 fixes the subtitle's TEXT ("Konu: … olarak kalır") but does not fix what else may share that line, and UX-02 requires the parent key to appear *somewhere* on this screen without inventing new vertical chrome (which would eat into UX-08's height budget). The subtitle prop on `ScreenHeader` already accepts `ReactNode` (not just a string) — composing the parent chip into that existing slot costs **zero additional height**, versus a dedicated new row which would cost ~24–28px and directly undercut the UX-08 arithmetic in §"D-19 compact token set" above. This is the ui-researcher's default per the auto-mode instruction to prefer the option that doesn't create a new problem while satisfying the locked requirement.

```
<ScreenHeader
  title={sideKey ? <TicketKeyLink .../> : <span className="text-sm font-semibold">Yeni konuşma</span>}
  subtitle={
    <span className="flex min-w-0 items-center gap-1.5">
      <ParentKeyChip parentKey={parentKey} size="compact" />
      <span className="min-w-0 flex-1 truncate">Konu: {subject || "Konu yok"}</span>
    </span>
  }
  ...
/>
```

`ParentKeyChip` is `shrink-0` (never truncates); the `"Konu: …"` text is the ONLY element in this row carrying `truncate` — exactly matching the "the key must never be the thing that truncates" hard constraint, extended symmetrically to the parent key.

### 4. `ParentBanner` (UX-03, D-11)

Renders on `conversations-list-screen.tsx` **instead of** the loading/empty/error/rows states, whenever `isSideConversation(ticket)` is true (see Pattern 2 hydration-flash guard below). Fills `ScreenContent`.

```
<div className="flex h-full flex-col items-center justify-center gap-3 px-6 text-center">
  <InfoCircledIcon className="size-8 text-muted-foreground" aria-hidden="true" />
  <div className="space-y-1">
    <h2 className="text-sm font-semibold text-foreground">Bu talep bir yan konuşma</h2>
    <p className="text-sm text-muted-foreground">
      Bu talep, aşağıdaki talebin yan konuşmasıdır. Buradan yeni bir yan konuşma başlatılamaz.
    </p>
  </div>
  <div className="flex items-center gap-2">
    <ParentKeyChip parentKey={parentKey} />
    <Button variant="outline" size="sm" asChild>
      <a
        href={buildAgentTicketUrl(tenantId, environment, parentKey)}
        target="_blank"
        rel="noopener noreferrer"
      >
        Üst talebe git
        <ExternalLinkIcon className="ml-1 size-3.5" aria-hidden="true" />
      </a>
    </Button>
  </div>
</div>
```

- **Tone:** informational, not an error — `text-muted-foreground`/`InfoCircledIcon`, never `text-destructive`/`ExclamationTriangleIcon`. This is the same icon (`InfoCircledIcon`) `InfoBox` uses (§5) — one icon, one consistent "heads up, not a failure" meaning across the whole panel.
- **`variant="outline"`** for the CTA button — matches the existing convention for secondary/navigational actions (`"Tekrar aç"`, `"Tekrar dene"` both use `outline`), keeping `default`(primary)-variant reserved for the single most-committing action per screen (Phase 2's `"Gönder"` precedent).
- **Uses `asChild`** (`button.tsx`'s existing `Slot`-backed prop) to render the button as a real `<a target="_blank" rel="noopener noreferrer">` — reuses D-07/D-08's exact navigation mechanism, no `window.open`.
- **"Yeni konuşma" header trailing button while the banner is shown:** stays visually present (no layout shift, matches Phase 1's D-13 disabled-CTA precedent) but `disabled`, `aria-label`/`title` = `"Yeni konuşma başlatılamaz — bu talep zaten bir yan konuşma"`.

**Hydration-flash guard (Pattern 2, RESEARCH.md):** `isSideConversation` is computed as `isHydrated(ticket) && Boolean(ticket.fieldMap[SIDE_CONVERSATION_PARENT_FIELD_KEY]?.value)`, where `isHydrated` checks `"fieldMap" in ticket`. During the brief provisional-ticket window after a ticket switch, this evaluates `false` — the banner is simply **absent** and the list renders its normal loading/rows state for that one frame-or-two. This is the safe failure direction (banner momentarily missing, never a false-positive block or a false-negative "you can start a new one" gap) and requires no additional UI state — it falls out of the predicate itself.

### 5. `InfoBox` (UX-06, D-16, D-17)

One component, two call sites, distinguished by a `dismissible` prop:

```
function InfoBox({ dismissible, onDismiss }: { dismissible: boolean; onDismiss?: () => void }) {
  return (
    <div className="flex items-start gap-2 border-b border-border bg-muted/40 px-3 py-2 text-xs text-muted-foreground">
      <InfoCircledIcon className="mt-0.5 size-3.5 shrink-0" aria-hidden="true" />
      <p className="min-w-0 flex-1">
        Bu işlem yeni bir talep oluşturur. Alan, atanan ve durum bilgileri otomatik
        dolmaz; gerekiyorsa talep ekranından manuel ayarlayın.
      </p>
      {dismissible && (
        <button
          type="button"
          aria-label="Bilgi kutusunu kapat"
          className="flex size-6 shrink-0 items-center justify-center rounded-full text-muted-foreground hover:bg-accent hover:text-accent-foreground focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2"
          onClick={onDismiss}
        >
          <Cross2Icon className="size-3" aria-hidden="true" />
        </button>
      )}
    </div>
  );
}
```

**Two placements (D-16):**
- **(a) Compose screen — persistent, `dismissible={false}`.** Renders as the FIRST child of `ScreenContent`'s inner column (above `RecipientField`). No dismiss button at all — this is the "always educate on this screen" surface.
- **(b) Chat screen — once, `dismissible={true}`.** Renders immediately below `ScreenHeader` (above the `solved`/`lifecycleError` bands and the message feed) **only** when: the conversation was just created in this session (i.e., immediately following `PanelNavigationStore.showPendingConversation`) AND `getInfoBoxSeen(tenantId)` (mirroring `last-seen-store.ts`'s exact shape, new key `sc:infoBoxSeen:{tenantId}`, RESEARCH.md Code Examples) is `false`. Clicking dismiss calls `setInfoBoxSeen(tenantId)` and unmounts the box — it never reappears in that tenant again, on any device (localStorage is device-local per D-16's own text, but "permanently" within one browser).

**Focus on dismiss:** clicking the dismiss button moves focus to the chat screen's back button (`ScreenHeader`'s `onBack` control, always present and focusable) — never left stranded on the now-unmounted dismiss button, consistent with this codebase's established "never leave focus stranded" rule (Phase 4's chip-removal focus-restoration precedent).

**Not a live region:** `InfoBox` is static informational content, not a status update — no `role="status"`/`role="alert"`. Its removal on dismiss is a discrete, user-initiated DOM change; no `aria-live` announcement is needed (the user just clicked its own dismiss button, they already know it closed).

### 6. `FormatMenu` — the "Aa" popover (UX-07, D-18)

**New toolbar order (D-18, locked):** `[Dosya ekle] [Aa ▾] [Geri al] [Yinele] … [Gönder]`. `TOOLBAR_ACTIONS`'s flat list is split: `attach`/`undo`/`redo` stay as direct toolbar buttons in that exact order; `bold`/`italic`/`heading`/`link`/`bulletList`/`orderedList`/`blockquote` (7 actions) move inside `FormatMenu`.

**Trigger:**
```
<Button
  ref={formatTriggerRef}
  type="button"
  variant="ghost"
  size="toolbar"
  aria-label="Biçimlendirme seçenekleri"
  aria-haspopup="menu"
  aria-expanded={formatMenuOpen}
  aria-controls={formatMenuOpen ? formatMenuId : undefined}
  className="w-auto gap-0.5 px-1.5 text-muted-foreground"
  onClick={() => setFormatMenuOpen((open) => !open)}
>
  <span className="text-xs font-semibold">Aa</span>
  <ChevronDownIcon className="size-3" aria-hidden="true" />
</Button>
```
(`size="toolbar"` is normally a fixed `h-8 w-8` square — this trigger overrides `w-8` to `w-auto` since it carries two-character text, not a single icon; height stays `h-8`, unchanged from every other toolbar control.)

**Panel — opens UPWARD, not downward:** the toolbar row sits at the visual bottom of the composer in both `compose` (composer is `flex-1`, filling remaining vertical space, toolbar is its last child) and `reply` (composer is `shrink-0`, docked at the screen bottom) modes — a downward-opening popover would routinely clip against the viewport edge. `bottom-full`, not `top-full`.

```
{formatMenuOpen && (
  <div
    ref={formatMenuRef}
    id={formatMenuId}
    role="menu"
    aria-label="Metin biçimlendirme seçenekleri"
    className="absolute bottom-full left-0 z-20 mb-1 max-h-64 w-56 overflow-y-auto rounded-md border border-border bg-card p-1 shadow-lg"
    onBlur={/* same relatedTarget/contains check as chat-screen.tsx's existing menu */}
  >
    {FORMAT_ACTIONS.map((action, index) => (
      <button
        key={action.command}
        ref={index === 0 ? formatFirstItemRef : undefined}
        type="button"
        role="menuitemcheckbox"
        aria-checked={editor?.isActive(action.activeName) ?? false}
        aria-label={action.label}
        className="flex min-h-11 w-full items-center gap-2 rounded px-3 py-2 text-left text-sm
                   text-foreground hover:bg-accent
                   aria-checked:bg-accent aria-checked:font-medium
                   focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-inset focus-visible:ring-ring"
        onClick={() => { runFormatAction(action); }}
      >
        {action.icon}
        <span>{action.label}</span>
      </button>
    ))}
  </div>
)}
```

- **7 items × `min-h-11` (44px) + `p-1` container padding** — panel content height ~316px, capped by `max-h-64` (256px) with `overflow-y-auto`; scrolls internally on very short viewports rather than ever being clipped off-screen. `w-56` (224px) comfortably fits inside the ~280px panel floor with room for the popover's own margin.
- **`heading`/`link` items:** clicking either closes `FormatMenu` and opens that action's EXISTING docked sub-panel (`headingMenuOpen`/`linkEditorOpen` — unchanged UI, unchanged state, unchanged tests) — these two sub-editors are NOT moved inside the popover itself, only their trigger relocates. This reuses proven, already-accessible code instead of rebuilding two working sub-editors inside a new floating container.
- **Active-state indication:** `aria-checked` + `bg-accent` — identical convention to the current toolbar's `pressed && "bg-accent text-foreground"`, just using the semantically-correct `menuitemcheckbox` role (these 7 actions are genuine toggles on the current selection) instead of a bare `menuitem`.

**Full keyboard contract** (mirrors `chat-screen.tsx`'s existing hand-rolled popover exactly, RESEARCH.md Pattern 3 — copied, not reinvented):
| Key | Behavior |
|---|---|
| Click/Enter/Space on trigger | Toggles panel; opening moves focus to the first `menuitemcheckbox` |
| `ArrowDown`/`ArrowUp` (while a menuitem is focused) | Moves focus to next/previous item, wrapping at the ends |
| `Enter`/`Space` (on a menuitem) | Activates the action; `bold`/`italic`/`bulletList`/`orderedList`/`blockquote` stay open (toggle-and-continue, matches current toolbar behavior of not auto-closing); `heading`/`link` close `FormatMenu` and open their own sub-panel |
| `Escape` | Closes panel, returns focus to the trigger |
| `Tab`/`Shift+Tab` | Closes panel WITHOUT forcing focus (lets natural tab order continue — matches `closeMenu(false)` in the existing precedent) |
| Outside `mousedown` | Closes panel, returns focus to the trigger |

### 7. Identity row (UX-05, D-13, D-14, D-15 — `thread-message.tsx`)

`senderLabel()` is rewritten (single function, no new component — matches P3's finding that the render pipeline needs zero new components):

```
function senderLabel(
  message: ThreadMessageData,
  showFullSender: boolean,
  agentEmail: string | null
): { text: string; isCurrentAgent: boolean } {
  if (message.internal) return { text: "İç not", isCurrentAgent: false };

  const name = message.senderName || message.senderEmail || "Gönderen";
  const text =
    showFullSender && message.senderName && message.senderEmail
      ? `${message.senderName} <${message.senderEmail}>`
      : name;
  const isCurrentAgent =
    message.direction === "own" &&
    agentEmail !== null &&
    message.senderEmail === agentEmail;

  return { text, isCurrentAgent };
}
```

- **Own-direction messages now render the ACTUAL author's name** (D-13: `comment.creator.fullName` for settled messages, the bootstrap `agentName` for still-pending optimistic bubbles) — not a hardcoded `"Siz"`. A teammate's own-direction message (another agent replying on the same side ticket) shows THAT agent's real name, no badge.
- **`"Siz"` becomes a badge NEXT TO the name**, only when `isCurrentAgent` is true (D-14):

```
<span className="flex min-w-0 items-center gap-1.5">
  <span aria-hidden="true" className="size-1.5 shrink-0 rounded-full bg-slate-400 ..." />
  <span className="min-w-0 truncate font-semibold text-foreground ...">{text}</span>
  {isCurrentAgent && (
    <span className="inline-flex shrink-0 items-center rounded-full bg-primary/10 px-1.5 py-0 text-[10px] font-semibold text-primary">
      Siz
    </span>
  )}
</span>
<time className="shrink-0 ...">{formatTime(message.createdAt)}</time>
```

- The name span keeps `min-w-0 truncate` (already present) so a long real name yields to the badge/timestamp rather than pushing them off — the header row's existing `flex items-center justify-between gap-3` layout already reserves `shrink-0` for `time`; the badge is added as a second `shrink-0` sibling, so truncation always lands on the NAME, never the badge or the timestamp.
- **Internal notes** (D-15): `senderLabel` returns exactly `"İç not"` — no name, no badge, matching the existing amber-bordered visual treatment (unchanged), just the shortened label text.

**Every new interactive element — accessible name, hit area, focus, keyboard:**

| Element | Accessible name | Hit area | Focus treatment | Keyboard |
|---|---|---|---:|---|
| `TicketKeyLink` | `"{KEY} talebini yeni sekmede aç"` | `h-8` (32px) | `focus-visible:ring-2 ring-ring ring-offset-2` | Native link — Enter activates, opens new tab |
| `ParentKeyChip` | `"Üst talep: {KEY}"` (non-interactive `aria-label` on the wrapping `<span>`) | not focusable (no `tabIndex`) | n/a | n/a — purely informational |
| `ParentBanner` CTA (`"Üst talebe git"`) | visible text = accessible name | `h-9` (Button `size="sm"` default) | existing `Button` focus-visible ring | Enter/Space via native `<a>` (Slot) |
| Disabled "Yeni konuşma" (banner active) | `"Yeni konuşma başlatılamaz — bu talep zaten bir yan konuşma"` | unchanged (`size="sm"`) | excluded from tab order while `disabled` (native browser behavior) | n/a while disabled |
| `InfoBox` dismiss | `"Bilgi kutusunu kapat"` | `size-6` (24px) — smallest already-accepted interactive size in this codebase (`AttachmentChip`'s `size-5` remove button precedent) | `focus-visible:ring-2 ring-ring ring-offset-2` | Enter/Space; moves focus to the screen's back button on activation |
| `FormatMenu` trigger | `"Biçimlendirme seçenekleri"` | `h-8` (`size="toolbar"`) | existing toolbar focus-visible pattern | Enter/Space opens, focus moves to first item |
| `FormatMenu` items (×7) | existing `TOOLBAR_ACTIONS` labels, unchanged | `min-h-11` (44px) | `focus-visible:ring-2 ring-inset ring-ring` | Arrow keys cycle (wrap), Enter/Space activates, Escape closes + returns focus, Tab closes without forcing focus |
| `"Siz"` badge | not independently interactive — decorative, the sender's real name (already announced via the preceding text node) carries the accessible content | n/a | n/a | n/a |

**`--interactive-target` is NOT overridden in compact mode** — D-19's own token list names `--panel-header-height`, `--panel-inset`, list-row height, and reply-editor min-height, but not `--interactive-target`. This is a deliberate accessibility floor: every `Button` `size="default"`/`"lg"`/`"icon"`/`"header"` stays at 40px (2.5rem) regardless of viewport height, even though `--panel-header-height` itself shrinks to 40px in compact mode — the header-sized button (`h-[var(--interactive-target)]`) then exactly fills the shrunk header with zero clipping and zero further reduction of its own hit area.

**Color never carries meaning alone (existing project rule, extended):** `TicketKeyLink`'s primary color is paired with an underline AND an `ExternalLinkIcon` (three independent signals it's a link, not two); `ParentKeyChip`'s neutral color is paired with the explicit `"üst talep"` text label (never color-only); the internal note's amber border/label pairing is unchanged.

**Untrusted input:** `sideKey`/`parentKey`/`tenantId` feeding `buildAgentTicketUrl` are always sourced from `useGrispi()`/`PanelNavigationStore.selectedConversation` (trusted context), never from `window.location`/the iframe hash — this is D-08's rule, unchanged and now also governing `ParentBanner`'s link (same function, same trust boundary, no new risk surface).

**`ParentBanner` receives no forced focus on mount** — it is reached via an external event (the host Grispi tab navigating to a different ticket, or the SDK's `currentTicketUpdated`), not a user click inside this panel, so no focus-steal is applied — consistent with this project's existing stance of never stealing focus on background/external state changes (e.g., list refresh already does not move focus).
