# Phase 04.2 Plan 09: Hoist the side-conversation link write + D-23 retry contract Summary

**`assertSideConversationLink`'s call moved ahead of `executeCreateMutation`'s `isCurrent` gates so the internal-note/parent-field PATCH is always attempted and awaited even when the agent switches conversations mid-create; its one retry now targets a new comment-free `patchTicketFields` primitive instead of repeating the note.**

## Accomplishments
- `executeCreateMutation` now starts `assertSideConversationLink` the instant `sideKey` is known, awaits it on every return path (both `isCurrent` early-returns and the main path), and keeps the cosmetic UI reconcile steps (`bindCreatedTicket`, `mutationAccepted`, `refreshCanonicalAfterMutation`) behind the original gates — closing SC1/UX-01 and SC9/UX-09
- Rewrote the locking test at `side-conversation-queries.test.tsx:1294` that previously asserted `addInternalNote` is "never called" on a session switch; it now asserts the PATCH is still attempted and the UI reconcile steps are still skipped
- Added `TicketFieldsPatchRequest` (comment-free, `fields`-only) and `Tickets.patchTicketFields` (`public/v1/tickets/{key}`, throws synchronously before `http.send` if the body carries `ts.status`) as a new, D-15-guarded write primitive

## Decisions Made
- The hoisted `linkAssertion` promise is created once and awaited explicitly at each of the three return points (both `isCurrent` early-returns, plus the main path before `refreshCanonicalAfterMutation`) rather than centralized in a wrapper — keeps every await site visible in the function body, matching the plan's explicit "never a dangling promise" requirement
- `patchTicketFields`'s `ts.status` guard is a runtime `throw` before any network call, not just a doc-comment convention — makes the D-15 boundary structurally enforced for this generic field-writer, independent of how carefully future callers are written
- D-23's retry body is constructed fresh (own `{ fields: [...] }` object literal) rather than derived from the `InternalNotePatchRequest` body via destructuring — the type itself (`TicketFieldsPatchRequest` has no `comment` member) is the guarantee that the retry cannot carry a comment, not a runtime strip step
