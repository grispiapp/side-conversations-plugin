# Phase 04.2 Plan 03: Thread message identity — real sender names, 'Siz' badge repositioned, shortened internal-note label Summary

**`senderLabel` no longer hardcodes `"Siz"` for every own-direction message — it now resolves the actual author's name (server `senderName`, or the bundled `agentName` for a still-pending optimistic bubble) and returns a separate `isCurrentAgent` flag that only renders the `"Siz"` badge as a distinct DOM element next to that name, never replacing it; the internal-note label is now exactly `"İç not"`.**

## Accomplishments
- `senderLabel(message, showFullSender, agentEmail, agentName)` rewritten to a 4-parameter pure function returning `{ text, isCurrentAgent }`; branch order matches UI-SPEC §7 (internal check first, then name resolution with the own-direction-only `agentName` fallback, then the existing `showFullSender` combined format, then `isCurrentAgent`)
- `ThreadMessageProps` gained two optional fields (`agentEmail?: string | null`, `agentName?: string | null`) — non-required, so every existing call site and test keeps compiling; real values are wired by Plan 06
- Identity row now renders the name span (`data-testid="sender-name"`, `min-w-0 truncate`) and, conditionally, a separate `"Siz"` badge span (`data-testid="sender-badge"`, exact UI-SPEC pill classes: `rounded-full bg-primary/10 px-1.5 py-0 text-[10px] font-semibold text-primary`, `shrink-0`) — truncation always lands on the name, never the badge or the `<time>` element
- Internal-note label reduced to exactly `"İç not"` — the `"· Salt okunur"` half is fully removed from the file (code, comments, and test strings)
- `ThreadMessageData` untouched — no new fields; `normalizeComment`/stores/`MessageVM` untouched, matching the plan's explicit prohibition

## Decisions Made
- `senderLabel` takes `agentName` as a genuine 4th parameter (matching the plan's `<action>` text, which is more specific than UI-SPEC §7's 3-param sketch) — needed to resolve D-13's pending-optimistic-message case, where the server hasn't assigned `senderName` yet
- `agentName` fallback fires only when `message.direction === "own"` AND `senderName` is absent — incoming messages never consult it, so a third party's blank name can never resolve to the active agent's bundled name
- Added `data-testid="sender-name"`/`"sender-badge"` purely as test hooks (not a new component/prop) to satisfy the plan's explicit requirement that badge-vs-name DOM separation be proven via separate queries, not a single combined-text assertion
- Task 1 intentionally shipped only a bare, unstyled conditional badge (no testid, no exact classes) so Task 2's structural/styling tests would genuinely fail before their implementation — preserving real RED phases across both TDD tasks in this plan rather than having Task 1 pre-empt Task 2's scope
