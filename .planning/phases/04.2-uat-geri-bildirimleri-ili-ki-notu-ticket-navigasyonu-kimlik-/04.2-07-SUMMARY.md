# Phase 04.2 Plan 07: Conversations list — parent banner (D-11) and narrow-panel button collapse (D-20) Summary

**Two hydration-safe pure predicates (`isHydratedTicket`, `isSideConversationTicket`, `parentKeyOfTicket`) drive a new `ParentBanner` that replaces the conversation list whenever the active ticket is itself a side conversation, blocking nested side conversations via a disabled-but-visible "Yeni konuşma" button, plus the "Yeni konuşma" button's text now collapses to an icon-only control below 320px so the list header never clips.**

## Performance

- **Duration:** ~25 min
- **Completed:** 2026-08-17
- **Tasks:** 2 (both `tdd="true"`)
- **Files modified:** 5 (1 created, 4 modified)

## Accomplishments

- **Task 1 — hydration-safe detection:** `isHydratedTicket(ticket)` checks the real object shape (`"fieldMap" in ticket`), never `ticket !== null` — `switchTicket`'s provisional `{ key }`-only ticket is real (RESEARCH.md Pattern 2, confirmed against `grispi-context.tsx` lines 109-148) and reading `fieldMap` off it must never throw. `isSideConversationTicket(ticket)` is the single predicate that will feed both the banner's visibility and the button's disabled state — it short-circuits on `isHydratedTicket` before ever touching `fieldMap`. `parentKeyOfTicket(ticket)` reuses `isSideConversationTicket` internally (not a duplicate hydration check) so the existence decision and the displayed parent key can never diverge.
- **Task 2 — `ParentBanner` + list-screen wiring:** New `ParentBanner` component (informational tone, `InfoCircledIcon`, neutral `ParentKeyChip`, `Button asChild` real `<a target="_blank" rel="noopener noreferrer">` CTA built from `buildAgentTicketUrl`) renders in place of the entire loading/rows/empty/error fragment via one top-level ternary in `ScreenContent`. The "Yeni konuşma" header button stays unconditionally rendered (no layout shift) but becomes `disabled` with an explanatory `aria-label`/`title` while the banner is shown; `PanelNavigationStore.openCompose` is untouched — the gate lives entirely at the caller (button). The button's visible label text is wrapped in a `<span className="hidden min-[320px]:inline">` for D-20's narrow-width collapse; the icon and full `aria-label` stay present at every width.

## Decisions Made

- `isHydratedTicket`/`isSideConversationTicket`/`parentKeyOfTicket` doc-comments deliberately avoid repeating the literal function name `isHydratedTicket` a third time (beyond its own definition and its one internal usage site) — matches the plan's own literal `grep -c 'isHydratedTicket' → 2` gate and the established Plan 01/02/06 convention of wording explanatory prose around forbidden/counted tokens rather than through them.
- `parentKeyOfTicket` calls `isSideConversationTicket` (not `isHydratedTicket` directly) and casts to `Ticket` afterward, rather than re-checking hydration inline — keeps the "single predicate, never re-derived" invariant intact and holds the exact-2 `isHydratedTicket` grep gate.
- `ConversationsListScreen`'s `ScreenContent` branches on `isSideConversation && parentKey` (both computed once, both null-safe) rather than asserting `parentKey!` — avoids a non-null assertion while remaining logically redundant-safe (both booleans are the same predicate applied to the same ticket in the same render).
- `ParentBanner`'s CTA renders as a **disabled** `Button` (not omitted) when `tenantId`/`environment` are unresolved, keeping the informational block's layout stable rather than having the CTA row appear/disappear.

## Issues Encountered

One test-authoring pitfall, self-corrected before commit: the "provisional ticket → then hydrated" scenario test initially called `render(<ConversationsListScreen />)` twice in a row without an intervening `render(<></>)` unmount. `ConversationsListScreen` is wrapped in `mobx-react-lite`'s `observer()`, which applies `React.memo` — a second `root.render()` call with the same element type and no changed props bails out without re-invoking the function body, so the mock's updated `ticket` value was never picked up. Fixed by inserting `render(<></>)` between the two states, matching the existing test file's own established pattern (used in the pre-existing "derives skeleton, empty, retry…" test) for exactly this reason.
