## 372px Layout Review

The shared shell is width-contained at approximately **372px** by construction:

- `Screen` is `min-w-0 overflow-hidden`; `ScreenContent` is `min-w-0 overflow-x-hidden`.
- The fixed header is exactly 48px (`--panel-header-height: 3rem`) and every screen uses `ScreenHeader`; there is no compose/detail one-off header.
- Header title/subtitle stacks, list row lines, recipient values, subjects, snippets, and long HTML use `min-w-0`, truncation, `break-words`, or `overflow-wrap:anywhere`.
- Ready rows are flush 72px separator rows. The unseen rail is absolutely positioned at 3px and does not change content width.
- Compose and sticky send/reply surfaces use the shared 16px inset; no negative margins or floating CTA overlaps exist.
- The single-line rich toolbar contains its own bounded horizontal scroller so 44px controls cannot enlarge the screen surface.
- The lifecycle menu is right-anchored within the shared header and uses a bounded minimum width.

This is an automated/source-level no-horizontal-overflow review plus a successful production build. It is not a claim of live iframe or tenant visual UAT.

## Keyboard, Names, Roles, and Focus

- Back, create, send, retry, disclosure, row, toolbar, menu, and dialog controls are native buttons with at least 44px targets and visible 2px `focus-visible` rings.
- Recipient search exposes combobox/listbox/option roles, `aria-controls`, `aria-activedescendant`, Arrow navigation, and Enter selection.
- Toolbar commands have Turkish accessible names and mark commands expose `aria-pressed`; Enter remains newline and Shift+Enter remains IME-safe submit.
- The lifecycle trigger exposes `aria-haspopup="menu"`/`aria-expanded`; opening focuses the menu item, Arrow/Home/End remain managed, Escape and outside click dismiss, and focus returns to the trigger.
- Confirmations expose `role="dialog"`, `aria-modal`, labelled/described relationships, initial safe-action focus, Escape cancellation, and focus restoration.
- Loading/empty/pending/lifecycle regions use scoped status roles; fetch, mutation, and failed-send errors use alert roles.
- Returning from detail consumes the activating-row key once and focuses that row, with the labelled create action as fallback.
