<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| List row → selected thread session | User activation pins side/parent/session and focus identity. |
| Tenant/parent/search input → Query key/API | Untrusted identifiers decide remote reads and cached result visibility. |
| Query result → UI/pure projection | Remote tickets, comments and users become rendered row/customer data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-03.1-07 | Information disclosure | rapid A→B navigation | mitigate | Synchronous complete tuple, monotonic sessionKey, no fetch in navigation, downstream session gates. |
| T-03.1-08 | Information disclosure | list/customer cache | mitigate | Exact tenant keys, no prior-key data carryover, enabled gates, rapid-key tests. |
| T-03.1-09 | Tampering | recipient rendering | mitigate | Preserve comment/user resolver and neutral fallback; never expose raw internal ticket key. |
| T-03.1-10 | Denial of service | search/list reads | mitigate | 300ms debounce, three-character threshold, size-10 pagination, no polling, self-throttled next page. |
| T-03.1-SC | Tampering | npm dependencies | mitigate | No package mutations; consume only Plan 02's committed Query dependency/contracts. |
</threat_model>
