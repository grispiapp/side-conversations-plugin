## Decisions Made

- Kept the activation seam strictly synchronous: tuple assignment and session increment precede `screen = "chat"` and perform zero API/store loads.
- Used the activating ticket row key itself as the focus identity because it is stable across mouse, Enter, and Space activation through native button semantics.
- Kept list repair failures inside row projection: only advanced-search failure surfaces a list error; hydration/user fallback failures remain neutral and never reveal raw ticket keys.
- Recomputed `hasUnseen` from localStorage when Query pages are selected/rendered, leaving server-owned lifecycle/action badges untouched.
- Returned empty customer rows while a normalized term is debouncing, so an earlier key can remain cached but can never render beneath current input.
