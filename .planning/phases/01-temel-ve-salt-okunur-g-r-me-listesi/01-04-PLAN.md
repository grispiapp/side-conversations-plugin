<objective>
Close the single Phase 1 verification gap (CORE-03 / ROADMAP Success Criterion 5): the production plugin/iframe bootstrap path in `src/contexts/grispi-context.tsx` has two unhandled failure points that leave the agent permanently stuck with NO Turkish error message and NO retry.

1. `plugin._init().then(...)` (line ~159) has no `.catch` — an SDK handshake rejection leaves the rocket `LoadingScreen` showing forever plus an unhandled promise rejection.
2. The initial `getTicket` failure (catch block ~173) only calls `console.error`; `setTicket` is never called → `ticket` stays `null` → the list screen's `ticket?.key` effect never fires `store.load()` → `store.status` stays at its constructor default `"loading"` forever (three skeleton rows, no error, no retry).

The fix routes the bootstrap initial fetch through the SAME resilient `switchTicket(bundle.context.ticketKey)` path standalone mode and `currentTicketUpdated` already use (provisional `{ key }` ticket set synchronously → `store.load()` fires regardless of hydration outcome → any API failure surfaces through the store's own `ErrorCard` + "Yeniden dene"), and adds the missing `.catch` on `_init()`. Because `grispi-context.tsx` is currently integration-only, the bootstrap wiring is extracted into a small pure, injectable function so both failure modes are unit-testable.

Purpose: Make CORE-03's layered error experience actually engage on the production (iframe) entry point — the exact code path the standalone UAT could not exercise.
Output: `src/contexts/plugin-bootstrap.ts` (`bootstrapPluginInit`), a refactored provider that calls it, focused tests, and a WR-05 nullability hardening on the same ErrorCard surface.
</objective>
