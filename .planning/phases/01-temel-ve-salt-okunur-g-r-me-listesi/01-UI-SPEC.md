# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Temel ve Salt Okunur Görüşme Listesi. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** Read-only conversation list screen only — list rows, badge states, empty state, loading skeleton, error card, "Daha fazla yükle" pagination. Compose ("+"), thread detail, reply, and file-attachment UI are OUT of scope (Phases 2-4); this contract only covers their disabled/placeholder appearance where D-13 requires them to already be visible.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no shadcn CLI. Hand-written components matching the existing local Radix + `cva`/`cn` convention already used by `button.tsx`/`input.tsx` (see Assumptions below) |
| Preset | not applicable |
| Component library | Radix UI primitives + `class-variance-authority` (existing project convention) |
| Icon library | `@radix-ui/react-icons` (already installed and used throughout `components/ui`) |
| Font | System default sans stack — no custom `fontFamily` declared in `tailwind.config.js` or `index.css`; Tailwind's default `font-sans` stack applies |

**Assumption (auto mode):** RESEARCH.md's "Alternatives Considered" documents that the current `shadcn` CLI registry has moved interactive primitives (Badge, Skeleton) to a Base UI foundation, which would be inconsistent with this repo's existing Radix+cva components (`button.tsx`, confirmed by direct read). Per that finding, this phase does NOT run `npx shadcn init` — new primitives (`Badge`, `Skeleton`) are hand-written against the existing local pattern instead. This is the ui-researcher's default per the auto-mode instruction to ground decisions in the actual starter codebase rather than block on a shadcn-init prompt.

## Spacing Scale

Declared values (8-point scale, multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside a badge; gap between meta fields (`·` separators) |
| sm | 8px | Gap between row's internal lines (subject / summary / meta row) |
| md | 16px | Default spacing: row internal padding (`px-4 py-3` ≈ 16/12px), gap between stacked list rows |
| lg | 24px | Empty-state / error-card internal padding, vertical gap between empty-state icon and heading |
| xl | 32px | Vertical breathing room above/below empty-state block within `ScreenContent` |
| 2xl | 48px | not used this phase (panel is 372px wide; reserved for future larger breaks) |
| 3xl | 64px | not used this phase |

Exceptions:
- **Unread rail width:** 3px (not on the 8pt scale — a hairline accent border on the left edge of "Yeni yanıt" rows, matching the mockup's purple rail; intentionally sub-scale since it's a decorative border, not a layout spacing unit).
- **Row minimum touch target:** rows are non-interactive in Phase 1 (see Open Question #4 in RESEARCH.md — default to non-clickable, no hover/press affordance), so no 44px touch-target exception is needed this phase.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.43 (20px) — row subject line, summary line, empty/error body copy |
| Label | 12px (`text-xs`) | 600 (semibold) | 1.33 (16px) — badge pill text, relative-time meta, recipient email (mono), page-load skeleton captions |
| Heading | 16px (`text-base`) | 600 (semibold) | 1.2 — `ScreenHeader`/`ScreenTitle` panel title ("Yan Görüşmeler") |
| Display | 18px (`text-lg`) | 600 (semibold) | 1.2 — empty-state heading ("Henüz yan görüşme yok") |

Weights used: **400 (regular)** and **600 (semibold)** only — exactly 2, per contract rule. (Note: RESEARCH.md's draft `badge.tsx` code example used `font-medium` (500); this contract overrides that to 600 semibold to stay within the 2-weight budget — executor should use `font-semibold`, not `font-medium`, on the Badge component.)

Recipient email / ticket-key strings render in `font-mono` (already a Tailwind default utility, no new font family) at Label size, per CONTEXT.md's "mono adres/anahtar dizgisi" note.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(210 40% 98%)` (slate-50, existing `--background`) | Screen background (`Screen` component already applies `bg-slate-50`) |
| Secondary (30%) | `hsl(0 0% 100%)` (white, existing `--card`) | Row cards, `ScreenHeader` bar, empty-state/error-card surfaces |
| Accent (10%) | `hsl(272 53% 37%)` (existing `--primary`, "mor") | Reserved for: (1) the left unread-rail accent border on "Yeni yanıt" rows, (2) the disabled "+" compose button's icon/outline (D-13), (3) focus rings (`--ring` reuse is separate but visually related), (4) the disabled empty-state CTA button. NOT used for body text, backgrounds, or the badge pills themselves. |
| Destructive | `hsl(0 84.2% 60.2%)` (existing `--destructive`) | Error-card icon/accent and "Yeniden dene" retry affordance only. No destructive user *actions* exist in Phase 1 (read-only phase) — this token is purely for the error-state visual, not a confirmation flow. |

Accent reserved for: unread-rail border, disabled "+" button icon, disabled empty-state CTA button, focus rings. Never used for row backgrounds, badge fills, or body/label text color.

RESEARCH.md's Open Question #5 flags this as unverified against the actual mockup pixels (the mockup URL is an authenticated client-rendered page neither the researcher nor this agent could fetch) — executor/checker should do a final visual diff against the mockup screenshot if/when Davut can share it, but should NOT block on it.

(per CONTEXT.md `<specifics>`: this sentence is the feature's identity and MUST appear in the empty state) |
| Empty state CTA | Same disabled "+" / "Yeni görüşme başlat" button as the primary CTA (single CTA per LIST-04 — not a second, separate button) |
| Error state — network failure | "Bağlantı sorunu nedeniyle yan görüşmeler yüklenemedi." + "Yeniden dene" button (`NetworkError` case, CORE-03) |

| Row hydration partial failure (silent, no user-facing copy) | Affected row renders dimmed/opacity-reduced with subject visible but summary omitted — no error text on the row itself; retried silently in the background (D-11) |
| Pagination CTA | "Daha fazla yükle" button; while loading, label is replaced by a spinner icon (no text change per D-14 — icon-only loading state to avoid layout width jumps) |
| Destructive confirmation | Not applicable — Phase 1 is read-only; no destructive actions exist in this phase's scope |

### Row anatomy (LIST-01/02/03, D-09)

Each row is a card (white, `--card`) with `rounded-md` corners, `md` (16px) internal padding, stacked vertically in a `sm` (8px) gap list within `ScreenContent`. Row content, top to bottom:
1. Meta line: recipient email (mono, Label) `·` relative time (Label, muted) — left-aligned; Badge pill — right-aligned, same line.
2. Subject line (Body, weight 400, single line truncate).
3. Summary line (Body, `text-muted-foreground`, single line truncate) — omitted/blank (not error text) if row hydration failed (D-11).

"Yeni yanıt" rows additionally render the 3px purple (`--primary`) left rail described in Color/Accent above — this is the row's only visual highlight mechanism for LIST-03's "görsel olarak vurgulanır."

### Screen states (state machine, no router — Pattern 2 in RESEARCH.md)

`loading` (3× `SkeletonRow`, D-14) → `empty` (EmptyState, LIST-04) | `error` (ErrorCard, D-11) | `ready` (grouped/sorted rows + "Daha fazla yükle" footer when more pages exist, D-12). On `currentTicketUpdated`, state resets synchronously to `loading` with zero stale-data flash (D-15) before the next fetch cycle starts.

### Panel width constraint

All layout must fit inside the ~372px iframe width (project constraint). Row text truncates with `line-clamp-1`/`truncate` rather than wrapping to multiple lines, to keep row height predictable across the list.
