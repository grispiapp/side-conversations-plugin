# Phase 04.1: Ortam yönlendirmesi ve prod hazırlığı - Research

**Researched:** 2026-08-10
**Domain:** Çalışma-zamanı API host çözümlemesi (frontend plugin, tek endpoint ailesi, 3 hedef ortam)
**Confidence:** HIGH

## Summary

Bu faz, saf bir mühendislik/keşif problemi değil — **çözümü zaten çalışan bir referans implementasyonda mevcut**. `vivollo-chat-side-plugin` reposunun `grispi-api-domain-param-ca0ee0` worktree'si (`/Users/davut/Code/grispiapp/vivollo-chat-side-plugin/.claude/worktrees/grispi-api-domain-param-ca0ee0/`), `side-conversations-plugin` ile neredeyse birebir aynı `GrispiProvider`/`HttpHandler`/`GrispiAPI` mimarisini kullanıyor ve `_grispi_env` + `dev` claim çözümlemesini üç dosyada (`environment.ts`, `http-handler.ts`, `grispi-context.tsx`) eksiksiz uyguluyor. Bu kod, backend'in `grispi-api` deposundaki `Environment.java`/`GrispiUrlGenerator.java` otoriter eşlemesiyle birebir tutarlı (preprod→`.net`, prod→`.com`, prod_tr→`.com.tr`).

Bu projenin (`side-conversations-plugin`) mevcut durumu: **tek bir hardcoded host** var — `src/grispi/client/http-handler.ts:27` (`baseUrl: string = "https://api.grispi.net"`). Bunun dışında hiçbir dosya ortam-bağımlı bir host inşa etmiyor; `objectUrl`/`objectThumbUrl` her yerde API'den tam nitelikli geliyor (bkz. Architecture Patterns → "usercontent hardcode yok" kanıtı). Plugin/standalone bootstrap akışı (`plugin-bootstrap.ts` → `grispi-context.tsx` → `switchTicket`) referans implementasyondaki `_init`/`currentTicketUpdated` akışıyla yapısal olarak aynı, tek fark bu projenin `bootstrapPluginInit` adında ayrı, injectable/test edilebilir bir fonksiyona sahip olması (referansta yok) — bu, çözümlemeyi eklemek için **daha temiz bir enjeksiyon noktası** sağlıyor.

Kritik uyum noktası: bu projede JWT decode yardımcı fonksiyonu (`parseJwt`) **yok** ve `Context` tipinde `dev` claim'i temsil eden bir alan yok (JWT'nin içinde, `bundle.context` seviyesinde değil). Referans implementasyon bunu `src/lib/utils.ts`'te saf bir fonksiyon olarak taşıyor; aynı deseni buraya taşımak (yeni npm paketi eklemeden) önerilir.

**Primary recommendation:** Referans implementasyonun üç dosyasını (`environment.ts`, `parseJwt` + `resolveGrispiEnvironment`, `HttpHandler.setEnvironment`) bu projenin mevcut dosya yapısına (ayrı `plugin-bootstrap.ts` enjeksiyon deseni + `standalone-dev.ts` pure-resolver deseni) uyarlayarak birebir taşı; yeni paket ekleme.

export function parseJwt(token: string) {
  var base64Url = token.split(".")[1];
  var base64 = base64Url.replace(/-/g, "+").replace(/_/g, "/");
  var jsonPayload = decodeURIComponent(
    window
      .atob(base64)
      .split("")
      .map(function (c) {
        return "%" + ("00" + c.charCodeAt(0).toString(16)).slice(-2);
      })
      .join("")
  );
  return JSON.parse(jsonPayload) as JwtToken;
}

### Bu projeye uyarlama farkı: `bootstrapPluginInit` enjeksiyon noktası
Referans implementasyon `grispi-context.tsx` içinde tek bir `useEffect`'te her şeyi yapıyor (ayrı bir `bootstrapPluginInit` yok). Bu proje ise CORE-03 gap-closure'da (`plugin-bootstrap.ts`) bootstrap'ı test edilebilir, saf bir fonksiyona çıkarmış. Yeni `setEnvironment` adımı bu projede REFERANSTAN FARKLI OLARAK `BootstrapPluginInitDeps` arayüzüne yeni bir enjekte edilebilir dep olarak eklenmeli — mevcut `setSettings`/`setAgentEmail`/`setTenantId` deseniyle birebir tutarlı:

```typescript
// src/contexts/plugin-bootstrap.ts — ÖNERİLEN DEĞİŞİKLİK (mevcut dosyaya ek)
export interface BootstrapPluginInitDeps {
  plugin: { _init(): Promise<GrispiBundle> };
  authentication: { setTenantId(tenantId: string): void; setToken(token: string): void; };
  setSettings(settings: Settings): void;
  setLoading(loading: boolean): void;
  setAgentEmail(email: string | null): void;
  setTenantId(tenantId: string | null): void;
  /** YENİ — CORE-04. switchTicket'tan ÖNCE çağrılmalı. */
  setEnvironment(environment: GrispiEnvironment): void;
  switchTicket(ticketKey: string): void;
}

export async function bootstrapPluginInit(deps: BootstrapPluginInitDeps): Promise<void> {
  try {
    const bundle = await deps.plugin._init();

    // CORE-04: switchTicket'tan (ilk gerçek fetch) ÖNCE, en başta çözümle.
    deps.setEnvironment(
      resolveGrispiEnvironment(bundle.settings, bundle.context.token)
    );

    deps.authentication.setTenantId(bundle.context.tenantId);
    deps.authentication.setToken(bundle.context.token);
    deps.setTenantId(bundle.context.tenantId);
    deps.setSettings(bundle.settings);
    deps.setAgentEmail(bundle.context.agent?.email ?? null);
    deps.setLoading(false);
    deps.switchTicket(bundle.context.ticketKey);       // ← env burada zaten set edilmiş olmalı
  } catch (err) {
    // reject dalı switchTicket'ı hiç çağırmıyor — env çözümlemesi gereksiz, değişiklik yok.
    ...
  }
}
```

### Anti-Patterns to Avoid
- **`useEffect` içinde asenkron olarak env çözmek (`await` sonrası):** `switchTicket` çağrısından SONRAKİ bir `await`'in ardına `setEnvironment` koymak — JS event loop'ta senkron kod bloğu bitmeden `fetch` tetiklenmiş olabilir. Referans implementasyon da bu proje de env çözümlemesini `await plugin._init()`'in HEMEN ardından, tamamen senkron bir kod bloğunda yapıyor; bu sıra korunmalı.
- **`_grispi_env` değerini normalize etmek (örn. `prod-tr` → `prod_tr` otomatik düzeltme):** Roadmap'in "Tuzak" notu bunu bilinçli bir davranış olarak tanımlıyor (strict eşleşme + `console.warn`); referans implementasyon da normalize ETMİYOR. Bu davranışı korumak, referans implementasyonla birebir tutarlılığı sağlar (bkz. Assumptions Log A4).
- **`HttpHandler.baseUrl`'i her API çağrısında parametre olarak geçirmek:** Referans implementasyon ve bu proje de `baseUrl`'i sınıf alanı (mutable, tek instance) olarak tutuyor — bu deseni bozup her `Tickets`/`Customers`/`Attachments` çağrısına ortam parametresi eklemek gereksiz bir refactor olur, kapsam dışı.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| JWT imza doğrulaması / tam JWT kütüphanesi | Genel amaçlı JWT verify/parse kütüphanesi entegrasyonu | Referans implementasyonun 12 satırlık `parseJwt`'i (imza doğrulamadan, sadece payload okur) | Bu plugin JWT'yi YETKİLENDİRME için değil, yalnızca bir routing ipucu (`dev` claim) okumak için kullanıyor; gerçek yetkilendirme zaten sunucu tarafında `Authorization` header doğrulamasıyla yapılıyor (bkz. Security Domain) |

**Key insight:** Bu fazda "hand-roll etme" prensibi TERSİNE çalışıyor — burada doğru yaklaşım, halihazırda üretimde çalışan referans implementasyonu birebir kopyalamak, kendi çözümünü icat etmemek. Roadmap bunu açıkça talep ediyor ("birebir kopyalanabilir").

## Common Pitfalls

### Pitfall 1: `HttpHandler.baseUrl` varsayılanının değişmesi mevcut testi kırar
**What goes wrong:** `src/grispi/client/http-handler.ts:27`'deki `baseUrl: string = "https://api.grispi.net"` değeri `GRISPI_BASE_URLS[DEFAULT_ENVIRONMENT]` (yani `"https://api.grispi.com"`, prod) olarak değişince, `src/grispi/client/__tests__/http-handler.test.ts:110-125` testindeki `expect(url).toBe("https://api.grispi.net/attachments/upload")` assertion'ı KIRILIR (`new HttpHandler()` hiçbir `setEnvironment` çağrısı yapmadan direkt `sendMultipart` çağırıyor, dolayısıyla sınıf-alanı varsayılanını test ediyor).
**Why it happens:** CORE-04'ün "varsayılan güvenli tarafa (prod) düşer" gereksinimi, sınıf-seviyesi varsayılanı preprod'dan (`.net`) prod'a (`.com`) değiştirmeyi gerektiriyor.
**How to avoid:** Planlayıcı bu satırı (`http-handler.test.ts:121`) `.com`'a güncelleyen bir görev eklemeli; bu beklenen/gerekli bir regresyon-testi düzeltmesi, kod hatası değil.
**Warning signs:** `npm test` çalıştırıldığında `http-handler.test.ts` "POSTs with cache: no-cache..." testi başarısız olur.

### Pitfall 2: Test fixture token'ları gerçek JWT değil — `parseJwt` savunmasız olursa bootstrap testleri çöker
**What goes wrong:** `src/contexts/__tests__/plugin-bootstrap.test.ts`'teki `makeBundle()` yardımcı fonksiyonu `token: "token-abc"` gibi nokta içermeyen, gerçek olmayan bir string kullanıyor (satır 37). `parseJwt` bunu `token.split(".")[1]` ile bölmeye çalışırsa `undefined` döner; `base64Url.replace(...)` bir `TypeError` fırlatır (`undefined` üzerinde `.replace` çağrısı).
**Why it happens:** Referans implementasyonun `parseJwt`'i try/catch içermiyor — gerçek Grispi JWT'leriyle hiç sorun çıkarmıyor ama test fixture'ları veya bozuk/eksik token'larla çökebilir.
**How to avoid:** Bu projeye taşınan `parseJwt`/`resolveGrispiEnvironment`, referanstan FARKLI olarak try/catch ile sarmalanmalı — parse hatasında `null` dönüp `resolveGrispiEnvironment`'ın `prod` varsayılanına düşmesini sağlamalı. Bu hem mevcut testleri kırılmadan geçirir hem de gerçek dünyada bozuk bir token'ın plugin'i çökertmesini engeller (güvenli-taraf prensibiyle tutarlı).
**Warning signs:** `plugin-bootstrap.test.ts`'e yeni `setEnvironment` dep'i eklendiğinde mevcut 4 test de (satır 52-97, 99-122, 124-154, 156-196) `setEnvironment: jest.fn()` almadan derlenmez (TypeScript required-field hatası) VE eğer parseJwt savunmasızsa "resolve branch" testleri `token: "token-abc"` fixture'ıyla runtime hatası fırlatır.

### Pitfall 3: `prod_tr` (alt çizgi) / `prod-tr` (tire) karışıklığı
**What goes wrong:** Grispi admin paneline `_grispi_env` ayarı `prod-tr` (backend'in kendi iç enum string'i, `Environment.java:99`) olarak girilirse, `isGrispiEnvironment("prod-tr")` `false` döner (yalnızca `"prod_tr"` `GRISPI_BASE_URLS`'te bir anahtar) — sessizce `dev` claim fallback'ine düşer, ki bu da muhtemelen `prod`'a düşer (TR tenant'ları normal prod token'ı kullanıyorsa `dev: false`) — TR trafiği yanlışlıkla `.com`'a gider, `.com.tr`'ye değil.
**Why it happens:** Backend'in kendi enum'u (`AsString.PROD_TR = "prod-tr"`) ile plugin ayar anahtarının beklediği değer (`prod_tr`, alt çizgi) kasıtlı olarak farklı — roadmap'in "Tuzak" notu bunu doğruluyor.
**How to avoid:** Kod tarafında normalize ETME (bkz. Anti-Patterns); bunun yerine README'de değeri net biçimde belgele (`_grispi_env` = `prod_tr`, alt çizgi, backend'in `prod-tr`'siyle KARIŞTIRMAYIN) — CORE-04 success criterion #5'in tam karşılığı.
**Warning signs:** TR tenant'ında API çağrıları `.com`'a gidiyor ama beklenen `.com.tr`; `console.warn("Unknown _grispi_env setting, falling back", "prod-tr")` konsolda görünür (referans implementasyonun zaten ürettiği sinyal, DevTools'ta aranabilir).

### Pitfall 4: Standalone dev modu, gerçek bundle/token olmadığı için `dev` claim fallback'ine giremiyor
**What goes wrong:** Standalone modda `bundle` hiç yok (SDK bypass edilmiş) — `resolveGrispiEnvironment(settings, token)` çağrılamaz çünkü gerçek bir Grispi JWT'si yok (`REACT_APP_DEV_TOKEN` gerçek bir Grispi token'ı olabilir de olmayabilir de — ne olduğu bu oturumda doğrulanamadı, `.env.development.local` dosyası izin ayarları nedeniyle okunamadı).
**Why it happens:** Standalone mod tasarım gereği bundle/SDK'yı tamamen atlıyor.
**How to avoid:** `StandaloneDevConfig`'e ayrı bir `environment: GrispiEnvironment` alanı eklenmeli, varsayılanı `"preprod"` (çünkü `DEFAULT_DEV_TENANT_ID = "gsocial-test"` ve mevcut `gsocial-test` akışı preprod'da yaşıyor — STATE.md "mevcut gsocial-test (preprod) akışı bozulmaz" notuyla CITED), `REACT_APP_DEV_GRISPI_ENV` env-var'ıyla override edilebilir olmalı (mevcut `REACT_APP_DEV_*` adlandırma konvansiyonuna uygun).
**Warning signs:** Standalone UAT sırasında istekler yanlışlıkla `.com`'a gider (gsocial-test tenant'ı orada mevcut değilse 401/404 alınır).

## Code Examples

### `src/lib/grispi-environment.ts` (YENİ dosya — önerilen tam içerik)
```typescript
// Source: referans deseni (vivollo-chat-side-plugin worktree) + bu projenin
// savunmacı hata-yönetimi konvansiyonuna (bkz. grispi-context.tsx satır 60-69
// "SOFT-FAIL GUARD") uyarlanmış hali — Pitfall 2'yi kapatmak için try/catch eklendi.
import {
  DEFAULT_ENVIRONMENT,
  GrispiEnvironment,
  isGrispiEnvironment,
} from "@/grispi/client/environment";
import { Settings } from "@/types/grispi.type";

interface DecodedJwt {
  dev?: boolean;
  [key: string]: unknown;
}

/** Base64url JWT payload decode — imza DOĞRULANMAZ (bkz. RESEARCH.md Security Domain). */
export function parseJwt(token: string): DecodedJwt | null {
  try {
    const base64Url = token.split(".")[1];
    if (!base64Url) return null;
    const base64 = base64Url.replace(/-/g, "+").replace(/_/g, "/");
    const jsonPayload = decodeURIComponent(
      atob(base64)
        .split("")
        .map((c) => "%" + ("00" + c.charCodeAt(0).toString(16)).slice(-2))
        .join("")
    );
    return JSON.parse(jsonPayload) as DecodedJwt;
  } catch {
    return null;
  }
}

/**
 * CORE-04: `_grispi_env` birincil kaynak; geçersiz/eksikse token'ın `dev`
 * claim'i ikincil kaynak (`dev: true` → preprod); hiçbiri çözümlenemezse
 * güvenli-taraf varsayılanı `prod`.
 */
export function resolveGrispiEnvironment(
  settings: Settings | null | undefined,
  token: string
): GrispiEnvironment {
  const setting = settings?.["_grispi_env"];

  if (isGrispiEnvironment(setting)) {
    return setting;
  }

  if (setting !== undefined) {
    console.warn(
      "grispi-environment",
      "Unknown _grispi_env setting, falling back",
      setting
    );
  }

  return parseJwt(token)?.dev === true ? "preprod" : DEFAULT_ENVIRONMENT;
}
```

## Security Domain

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | Hayır (bu faz) | Token'ın kendisi zaten `Authentication` sınıfı tarafından `Authorization` header'ına konuyor; bu faz yalnızca hangi HOST'a gönderileceğini seçiyor, doğrulamayı değiştirmiyor |
| V5 Input Validation | Evet | `isGrispiEnvironment` strict allowlist kontrolü (`value in GRISPI_BASE_URLS`) — `_grispi_env` ayarı asla doğrudan bir URL parçası olarak enterpolasyon EDİLMİYOR, yalnızca sabit bir map'te anahtar olarak kullanılıyor (SSRF/host-injection riski yok, çünkü değer asla `fetch()`'e serbest string olarak geçmiyor) |
| V6 Cryptography | Kısmen | `parseJwt` JWT'yi İMZA DOĞRULAMADAN okuyor (bkz. Don't Hand-Roll) — bilinçli, çünkü bu claim yetkilendirme kararı için değil yalnızca UX/routing ipucu için kullanılıyor; asıl auth zaten sunucuda `Authorization: Bearer <token>` doğrulamasıyla yapılıyor |

### Known Threat Patterns for bu stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Sahte/bozuk `dev` claim ile yanlış host'a yönlendirme | Tampering (istemci tarafı, düşük etki) | Worst-case senaryo: istemci preprod (`.net`) yerine prod'a (`.com`) gider veya tersi — gerçek `Authorization` header'ı hedef host'ta geçersizse istek zaten 401 ile reddedilir; kullanıcı verisi sızmaz, yalnızca "yanlış tenant'a bağlanamıyorum" hatası görülür. | `_grispi_env` ayarına keyfi string enjeksiyonu (host injection / SSRF) | Tampering / SSRF | `isGrispiEnvironment` allowlist'i, `_grispi_env` değerinin ASLA `fetch()` URL'ine doğrudan interpolasyon edilmemesini garanti ediyor — yalnızca 3 sabit, kod-içi tanımlı URL'den biri seçilebiliyor.
