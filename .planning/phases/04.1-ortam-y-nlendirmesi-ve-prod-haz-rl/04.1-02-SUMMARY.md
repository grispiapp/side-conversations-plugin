**Standalone dev mode now carries its own allowlist-gated environment override (`REACT_APP_DEV_GRISPI_ENV`, defaulting to `preprod`) wired ahead of its first fetch, and README documents `_grispi_env`'s three values, unset behavior, TR-mandatory rule, and hyphen trap — closing out CORE-04's remaining SC3/SC5 gaps.**

## Accomplishments

- `StandaloneDevConfig` gained a required `environment: GrispiEnvironment` field and `DEFAULT_DEV_ENVIRONMENT` (`"preprod"`) — standalone dev mode bypasses the bundle/SDK entirely so it can never enter the real `_grispi_env` → JWT `dev` claim → prod chain (Plan 04.1-01); it needs, and now has, its own override.
- `REACT_APP_DEV_GRISPI_ENV` is resolved through `isGrispiEnvironment`, not the file's existing `?.trim() || DEFAULT` pattern — an unrecognized value (the backend's hyphenated `prod-tr`, `"staging"`, empty string) falls back to `preprod` instead of leaking through untyped (T-04.1-01).
- `grispi-context.tsx`'s standalone branch now calls `grispiAPI.setEnvironment(standaloneConfig.environment)` immediately after `setToken` and strictly before `switchTicket` fires the first real request — verified by source-order inspection (the same discipline Plan 04.1-01 established for the plugin-mode branch via `invocationCallOrder`).
- README gained a new `### Required setting: _grispi_env` section: the three valid values (matched 1:1 against `GRISPI_BASE_URLS` keys), what happens when the setting is absent (falls to the JWT `dev` claim, then to the safe-side `prod` default — never TR prod by accident), a `> **Important**` block on why TR installs must set it manually (`dev = !(PROD || PROD_TR)` cannot distinguish prod from TR prod), and a dedicated hyphen-trap warning (`prod-tr` is invalid; correct spelling is `prod_tr`).
- README's `### Example settings` JSON block and the tenant-setup step 2 now reference `_grispi_env`; the Local Testing section documents the standalone-only `REACT_APP_DEV_GRISPI_ENV` override.
- Full test suite (367 tests, 30 suites) and `tsc --noEmit` both green; SC4's static host-literal grep gate re-confirmed empty; zero new npm dependencies.

## Decisions Made

- `DEFAULT_DEV_ENVIRONMENT` is `"preprod"`, intentionally the opposite of the real chain's safe-side `DEFAULT_ENVIRONMENT` (`"prod"`) — `DEFAULT_DEV_TENANT_ID` (`gsocial-test`) lives on preprod, so defaulting standalone mode to prod would silently break every existing local UAT flow the moment this plan landed. The plan's own `<behavior>` spec called this out explicitly and it was implemented as specified.
- The allowlist gate (`isGrispiEnvironment`) was applied exactly as the plan's prohibition (T-04.1-01) required, deliberately NOT copying the neighboring fields' `?.trim() || DEFAULT` idiom for this one field — a plain `||` fallback would have let an unrecognized string (including the backend's internal hyphenated spelling) reach `StandaloneDevConfig.environment` untyped.
- README's TR-mandatory rule and hyphen trap were written as separate, explicit prose blocks (a `> **Important**` blockquote and a labeled "Hyphen trap" paragraph) rather than folded into the value table — SC5's mitigation for T-04.1-06 is documentation-only (the JWT `dev` claim genuinely cannot distinguish prod from TR prod), so the warning has to be unmissable to function as a mitigation at all.
