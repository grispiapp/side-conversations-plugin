# Phase 04.1: Code Review Report

**Reviewed:** 2026-08-10
**Depth:** standard
**Files Reviewed:** 11
**Status:** issues_found

## Summary

CORE-04 routes the plugin to the correct Grispi host by resolving
`_grispi_env` → JWT `dev` claim → `prod`, then pushing the resolved key into a
single shared `HttpHandler`. The shape of the design is sound: hosts are
centralized in `environment.ts`, the setting is used as a map key rather than
concatenated into a URL, `parseJwt` is fully wrapped in try/catch, and
`setEnvironment` is a required (non-optional) dep so a call site cannot silently
omit it. All 41 tests in the four touched suites pass.

The design intent is nonetheless violated in one place that matters. The
allowlist guard `isGrispiEnvironment` uses the `in` operator, which walks the
prototype chain — so `__proto__`, `constructor`, `toString`, `valueOf` and
`hasOwnProperty` all pass the "strict allowlist match" and are then used as
lookup keys into `GRISPI_BASE_URLS`. The resulting `baseUrl` is not a URL at
all, and `fetch()` falls back to resolving the request relative to the plugin's
own origin, carrying the agent's `Authorization: Bearer <token>` header with it.
That is exactly threat T-04.1-01 (untrusted `_grispi_env` reaching a request
URL), reachable from both the tenant setting and `REACT_APP_DEV_GRISPI_ENV`.

Second-order concern: the terminal link of the whole feature — `GrispiEnvironment`
key → `HttpHandler.baseUrl` mutation → actual host in `fetch()` — has **zero**
test coverage. Every bootstrap test injects `setEnvironment: jest.fn()`, and no
test anywhere in `src/` calls the real `HttpHandler.setEnvironment` or
`GrispiAPI.setEnvironment`. A no-op implementation of both would pass the entire
suite. Combined with the default host flipping from `api.grispi.net` (preprod) to
`api.grispi.com` (prod) in this diff, an un-set environment now fails toward
production instead of preprod, which makes the untested pre-bootstrap window
materially more dangerous than it was before.

## Narrative Findings (AI reviewer)

### Critical Issues

#### CR-01: `isGrispiEnvironment` allowlist is bypassable via the prototype chain — leaks the agent bearer token to the plugin's own origin

**File:** `src/grispi/client/environment.ts:17-21`
(reached from `src/lib/grispi-environment.ts:59` and `src/lib/standalone-dev.ts:80`)

**Issue:** The guard is `typeof value === "string" && value in GRISPI_BASE_URLS`.
The `in` operator checks the **entire prototype chain**, not own properties.
`GRISPI_BASE_URLS` is a plain object literal, so it inherits from
`Object.prototype`. Verified in node:

```
"toString"      in GRISPI_BASE_URLS === true
"constructor"   in GRISPI_BASE_URLS === true
"__proto__"     in GRISPI_BASE_URLS === true
"valueOf"       in GRISPI_BASE_URLS === true
"hasOwnProperty" in GRISPI_BASE_URLS === true
```

Full attack path with `settings["_grispi_env"] = "__proto__"` (a per-tenant
plugin setting, explicitly untrusted per T-04.1-01):

1. `resolveGrispiEnvironment` — `isGrispiEnvironment("__proto__")` returns `true`,
   so the "strict allowlist match" branch returns `"__proto__"` as a
   `GrispiEnvironment`. **No warning is logged**, and the JWT/`prod` fallback
   chain is never reached.
2. `HttpHandler.setEnvironment` — `GRISPI_BASE_URLS["__proto__"]` evaluates to
   `Object.prototype`, and `setBaseUrl` assigns it to `this.baseUrl` (declared
   `string`; TypeScript cannot see this because the key type-checks as a valid
   `GrispiEnvironment`).
3. `HttpHandler.send` — `` `${this.baseUrl}/${url}` `` stringifies to
   `"[object Object]/public/v1/tickets/TICKET-1"`. `fetch()` treats that as a
   **relative URL** and resolves it against the plugin iframe's origin.
4. The request carries `Authentication.headers` — `tenantId` and
   `Authorization: Bearer <bundle token>` — to a host that is not a Grispi API
   host. With `"constructor"` / `"toString"` the base becomes
   `"function Object() { [native code] }"`, which is also a relative path.

The unit test at `src/lib/__tests__/grispi-environment.test.ts:92-102` only
probes `"https://evil.example.com"`, which fails the `in` check for the wrong
reason and therefore gives false assurance that the allowlist holds.

**Fix:** use an own-property check, and add regression cases for the prototype keys.

```ts
// src/grispi/client/environment.ts
export const isGrispiEnvironment = (
  value: unknown
): value is GrispiEnvironment => {
  return (
    typeof value === "string" &&
    Object.prototype.hasOwnProperty.call(GRISPI_BASE_URLS, value)
  );
};
```

```ts
// src/lib/__tests__/grispi-environment.test.ts — regression guard
it.each(["__proto__", "constructor", "toString", "valueOf", "hasOwnProperty"])(
  "rejects the inherited prototype key %s",
  (key) => {
    expect(isGrispiEnvironment(key)).toBe(false);
    expect(resolveGrispiEnvironment({ _grispi_env: key }, "not-a-jwt")).toBe(
      "prod"
    );
  }
);
```

Defence in depth (cheap, and closes the class of bug rather than the instance):
create the map with a null prototype — `Object.freeze(Object.assign(Object.create(null), {...}))` —
or assert at the boundary that the looked-up value is a string starting with
`https://` before assigning it to `baseUrl`.

### Warnings

#### WR-01: `currentTicketUpdated` is wired before bootstrap resolves — a ticket switch in that window fetches from the *production* host with no auth headers

**File:** `src/contexts/grispi-context.tsx:184-199`

**Issue:** `bootstrapPluginInit(...)` is fire-and-forget (`void`), so it returns
at its first `await` (`plugin._init()`). The very next statement installs
`plugin.currentTicketUpdated`, which calls `switchTicket` → `getTicket` →
`HttpHandler.send`. If the SDK emits a ticket change before `_init()` settles,
that request is issued while:

- `baseUrl` is still the class default, and this diff changed that default from
  `https://api.grispi.net` (preprod) to `https://api.grispi.com` (prod) —
  `src/grispi/client/http-handler.ts:33`. A preprod tenant's ticket key is now
  sent to the **production** host instead of preprod.
- `Authentication.headers` is empty — no `tenantId`, no `Authorization`.

The phase's stated invariant is "no request is ever issued against the wrong
host"; this path violates it. The same window also exists for any other consumer
that can trigger a query before bootstrap resolves.

**Fix:** do not accept ticket events until bootstrap has applied the
environment, and register the handler after the bootstrap promise settles.

```tsx
const bootstrappedRef = useRef(false);

const switchTicket = useCallback(async (ticketKey: string) => {
  if (!ticketKey || !bootstrappedRef.current) return;
  // ...
}, []);

// inside the effect
void bootstrapPluginInit({ ... }).finally(() => {
  bootstrappedRef.current = true;
  plugin.currentTicketUpdated = async (t: Ticket) => void switchTicket(t.key);
});
```

(Set `bootstrappedRef.current = true` from inside the bootstrap's success path —
right after `setEnvironment` — if the initial `switchTicket` must still run.)

#### WR-02: The terminal link of CORE-04 is completely untested — a no-op `setEnvironment` passes the whole suite

**Files:** `src/grispi/client/http-handler.ts:42-45`, `src/grispi/client/api.ts:26-29`,
`src/grispi/client/__tests__/http-handler.test.ts` (whole file)

**Issue:** Nothing in `src/` exercises the real `setEnvironment`. Confirmed by
grep: the only occurrences of `setEnvironment` in any test file are the
`jest.fn()` stubs in `plugin-bootstrap.test.ts`. `http-handler.test.ts` imports
`GRISPI_BASE_URLS`/`DEFAULT_ENVIRONMENT` only to assert the *default* URL
(line 122-124) — it never calls `setEnvironment`. `GrispiAPI.setEnvironment`'s
delegation to the private `httpHandler` has no test at all, and
`grispi-context.tsx` (which holds both real call sites: the standalone call at
line 152 and the `.bind` at line 191) is not rendered by any test in the repo.

Consequence: if `HttpHandler.setEnvironment` were an empty method, or if
`GrispiAPI.setEnvironment` forgot to delegate, every test in the phase would
still be green while 100% of traffic went to the default host. The three host
URLs themselves are also asserted nowhere.

**Fix:** add end-to-end assertions that the key actually reaches `fetch`.

```ts
// src/grispi/client/__tests__/http-handler.test.ts
it.each([
  ["preprod", "https://api.grispi.net"],
  ["prod", "https://api.grispi.com"],
  ["prod_tr", "https://api.grispi.com.tr"],
] as const)("routes requests to %s host after setEnvironment", async (env, host) => {
  const fetchSpy = jest.spyOn(global, "fetch").mockResolvedValue({
    ok: true, status: 200, json: () => Promise.resolve({}),
  } as unknown as Response);

  handler.setEnvironment(env);
  await handler.send("public/v1/tickets/T-1", { method: "GET" });

  expect(fetchSpy.mock.calls[0][0]).toBe(`${host}/public/v1/tickets/T-1`);
});

it("defaults to the prod host before setEnvironment is ever called", () => {
  expect(new HttpHandler().baseUrl).toBe("https://api.grispi.com");
});
```

Plus one test on `GrispiAPI` proving `grispiAPI.setEnvironment("preprod")`
changes the host used by `grispiAPI.tickets.getTicket`.

#### WR-03: Newly-added public `setBaseUrl` is an unrestricted arbitrary-host setter with zero callers

**File:** `src/grispi/client/http-handler.ts:38-40` (also `baseUrl` public at line 33)

**Issue:** `setBaseUrl(baseUrl: string)` was introduced by this diff and is used
by exactly one caller — `setEnvironment`, three lines below it. Grep confirms no
other reference anywhere in `src/`. As a public API it is a documented,
discoverable escape hatch that bypasses `GRISPI_BASE_URLS` entirely, which
directly undercuts the phase's core invariant ("`environment.ts` is the only
legitimate home for environment-dependent hosts", T-04.1-02): the next developer
who needs a one-off host has a sanctioned method to hardcode one. `baseUrl`
itself is likewise a public mutable field that can be reassigned to any string.

**Fix:** make both non-public so the allowlist is the only entry point.

```ts
export class HttpHandler {
  private baseUrl: string = GRISPI_BASE_URLS[DEFAULT_ENVIRONMENT];

  setEnvironment(environment: GrispiEnvironment) {
    this.baseUrl = GRISPI_BASE_URLS[environment];
  }
  // ...
}
```

If the field must stay readable for tests, expose `get currentBaseUrl(): string`
rather than a setter.

#### WR-04: `switchTicket` dep is typed `void` but is actually `async` — floating promise inside the `try`, and a sync throw would undo the bootstrap

**Files:** `src/contexts/plugin-bootstrap.ts:51,74`; implementation at
`src/contexts/grispi-context.tsx:98`

**Issue:** `BootstrapPluginInitDeps.switchTicket` is declared
`switchTicket(ticketKey: string): void`, but the injected implementation is an
`async` `useCallback` returning `Promise<void>`. Two consequences:

1. `deps.switchTicket(bundle.context.ticketKey)` at line 74 is an unhandled
   floating promise. The type annotation actively hides this from both the reader
   and any `no-floating-promises` lint. Today the implementation catches
   internally, but nothing enforces that for future implementations — and the
   docblock at lines 9-16 explicitly advertises "the returned promise always
   resolves / never produces an unhandled rejection", a guarantee this call
   silently gives up on.
2. It is the last statement inside the `try`. Any synchronous throw from a future
   `switchTicket` (or from `setEnvironment`/`setSettings` above it) lands in the
   `catch`, which then runs `setTenantId(null)` — wiping a tenant id that was
   already successfully applied at line 70 and leaving the app in a
   half-bootstrapped state (env applied, token applied, tenant null).

**Fix:**

```ts
// widen the contract to the truth, and mark the call explicitly fire-and-forget
switchTicket(ticketKey: string): void | Promise<void>;

// ...at the call site, outside the try:
let bundle: GrispiBundle;
try {
  bundle = await deps.plugin._init();
  deps.setEnvironment(resolveGrispiEnvironment(bundle.settings, bundle.context.token));
  // ...remaining sync wiring...
} catch (err) {
  console.error("grispi-context", "_init failed", err);
  deps.setTenantId(null);
  deps.setLoading(false);
  return;
}
void deps.switchTicket(bundle.context.ticketKey);
```

#### WR-05: The `setEnvironment`-before-`switchTicket` ordering test does not test what it claims

**File:** `src/contexts/__tests__/plugin-bootstrap.test.ts:101-106`

**Issue:** The assertion is
`setEnvironment.mock.invocationCallOrder[0] < switchTicket.mock.invocationCallOrder[0]`,
labelled "must complete before the first real fetch". Call order is preserved
regardless of whether an `await` is inserted between the two calls, so this test
passes unchanged if someone introduces the exact async gap the docblock at
`plugin-bootstrap.ts:60-63` warns against ("no `await` between here and
`switchTicket` may be introduced"). The invariant that is actually load-bearing —
no fetch can be issued between the two — is asserted by nothing. There is also no
test covering the JWT `dev: true` → `preprod` path *through* `bootstrapPluginInit`
(only through `resolveGrispiEnvironment` directly).

**Fix:** assert against real state rather than call order — drive the real
`HttpHandler` and check the host observed by a mocked `fetch` inside
`switchTicket`:

```ts
const handler = new HttpHandler();
let hostAtFetchTime: string | undefined;
const switchTicket = () => { hostAtFetchTime = handler.baseUrl; };

await bootstrapPluginInit({
  ...,
  setEnvironment: (e) => handler.setEnvironment(e),
  switchTicket,
});

expect(hostAtFetchTime).toBe("https://api.grispi.net"); // for a dev:true bundle
```

#### IN-02: Standalone mode silently swallows an unrecognized `REACT_APP_DEV_GRISPI_ENV`, and a test locks the silence in

**File:** `src/lib/standalone-dev.ts:79-82` (tests at
`src/lib/__tests__/standalone-dev.test.ts:148-182`)

**Issue:** The plugin path warns on an unknown `_grispi_env`
(`grispi-environment.ts:63-69`), but the dev path falls back to `preprod` with
no diagnostic. A developer who writes `REACT_APP_DEV_GRISPI_ENV=prod-tr` (the
backend's own hyphenated spelling — the exact trap the code comment calls out)
or `production` gets preprod with zero feedback, and will conclude the variable
is broken. The current tests assert the fallback value but not the absence of a
warning, so adding one is non-breaking.

**Fix:** mirror the plugin path.

```ts
const rawEnvironment = env.REACT_APP_DEV_GRISPI_ENV?.trim();
if (rawEnvironment && !isGrispiEnvironment(rawEnvironment)) {
  console.warn(
    "standalone-dev",
    "Unknown REACT_APP_DEV_GRISPI_ENV, falling back",
    rawEnvironment
  );
}
```

#### IN-03: Warning echoes the raw untrusted setting value, and fires on empty string

**File:** `src/lib/grispi-environment.ts:63-69`

**Issue:** The unrecognized value is logged verbatim to the browser console —
an attacker-supplied tenant setting is an attacker-supplied console log line
(ANSI/format noise, arbitrarily long strings). Separately, the condition is
`setting !== undefined`, so a tenant that stores `_grispi_env: ""` to mean
"unset" produces a warning on every load, and a JSON `null` logs `null`.

**Fix:** truncate and only warn for a non-empty value.

```ts
if (typeof setting === "string" && setting.trim() !== "") {
  console.warn(
    "grispi-environment",
    "Unknown _grispi_env setting, falling back",
    setting.slice(0, 32)
  );
}
```

#### IN-04: No cleanup for `plugin.currentTicketUpdated`; StrictMode double-invokes the whole bootstrap

**File:** `src/contexts/grispi-context.tsx:139-201`

**Issue:** The effect has no cleanup function, so `plugin.currentTicketUpdated`
is never detached, and under `React.StrictMode` (enabled at
`src/index.tsx:13`) the effect body runs twice in development — two `_init()`
handshakes, two `setEnvironment` calls, two `switchTicket`/`getTicket` fetches.
`setEnvironment` is idempotent so there is no correctness impact today, but the
duplicate `_init()` doubles the SDK handshake and the initial network cost, and
the phase's new env-resolution code now sits on that duplicated path.

**Fix:** return a cleanup that clears the handler, and guard the bootstrap with a
ref so the second StrictMode pass is a no-op.

#### IN-05: `parseJwt` casts any JSON value to `DecodedJwt` without checking it is an object

**File:** `src/lib/grispi-environment.ts:33`

**Issue:** `JSON.parse(jsonPayload) as DecodedJwt` accepts primitives and arrays.
A token whose payload segment decodes to `7`, `"x"` or `[1,2]` is returned as a
`DecodedJwt`, so the declared type is a lie for anything downstream that trusts
it. Harmless at the single current call site (`?.dev` yields `undefined` →
falls through to `prod`), but it is an unchecked cast on parsed untrusted input.
Related: in a non-browser environment `atob` is undefined, so the `catch`
silently degrades every `dev: true` token to `prod` with no diagnostic.

**Fix:**

```ts
const parsed: unknown = JSON.parse(jsonPayload);
if (typeof parsed !== "object" || parsed === null || Array.isArray(parsed)) {
  return null;
}
return parsed as DecodedJwt;
```
