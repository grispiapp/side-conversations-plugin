<objective>
Switch the project to a repo-as-host deploy model: the built output is committed
to this repository, because `grispi.app` serves the repo's contents directly.
There is no separate hosting or CI pipeline.

Purpose: the plugin is currently undeployable as documented. The recorded
hosting URL points at CRA's `public/` directory, which holds the raw,
unprocessed `index.html` template — `%PUBLIC_URL%` placeholders, no bundle. It
could never have worked. The real artifact is the build output, and that output
is git-ignored, so it never reaches the host at all.

Output:
- the untracked-block for the build directory removed from `.gitignore`
- `.env.production` with `GENERATE_SOURCEMAP=false` (the build is 4.3 MB today,
  of which 3.4 MB is a single JS map — high-churn generated content that would
  otherwise enter this public repo's history permanently and irreversibly)
- README manifest `src` and install flow rewritten to the real flow
- build output regenerated and committed, matching the source at this commit
</objective>

<decisions>

**D-01 — Source maps are disabled via a committed `.env.production`, not inline in the `build` script.**
Inlining (`"build": "GENERATE_SOURCEMAP=false craco build"`) is a shell-prefix
assignment: it silently fails on Windows `cmd`/PowerShell, producing a 4.3 MB
build for that developer with no warning. A `.env.production` file is read by
CRA's own env loader on every production build regardless of who runs it, from
which shell, or via which wrapper (`npm run build`, `CI=true npm run build`,
`npx craco build`) — all of which set `NODE_ENV=production`.

`.env.production` is chosen over a bare `.env` because it is scoped exactly to
production builds and therefore cannot influence `npm start` or the test run.
(Development source maps are unaffected either way — CRA's dev `devtool` does
not consult this flag — but the narrower file removes the question entirely.)

`.gitignore` already ignores `.env.production.local` and NOT `.env.production`,
so the new file is tracked without further gitignore changes.

**D-02 — Disabling maps is a repo-bloat decision, not a secrecy one.**
This repository is public; the source is already readable. The map leaks nothing
new. The reason is 3.4 MB of regenerated content per deploy commit, which git
cannot forget once pushed. The developer explicitly approved turning maps off.

**D-03 — Drift is handled by a documented rule, not tooling.**
Committing generated output means every source change needs a matching rebuild
commit or the live plugin silently keeps serving the old bundle. This task makes
the rule visible in README section 4. Building enforcement (a pre-commit hook or
a CI staleness check) is deliberately out of scope here.

</decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local build env -> public git repo | Anything the bundler inlines at build time becomes world-readable and permanent once pushed |
| public git repo -> grispi.app -> tenant iframe | The committed bundle is executed verbatim in agents' browsers; the repo IS the release channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-m8f-01 | Information Disclosure | committed build output in a public repo | high | mitigate | Task 3 greps the built output for the `REACT_APP_DEV_TOKEN` value read from the git-ignored `.env.development.local` and fails the task on a hit. The token cannot structurally be inlined (that file loads only at `NODE_ENV=development`), but the assertion is cheap and the failure mode is irreversible. |
| T-m8f-02 | Information Disclosure | the JS source map | low | accept | Repo is public; the map exposes no source that is not already readable. Maps are removed for repo-size reasons (D-02), not confidentiality. |
| T-m8f-03 | Tampering | source/bundle drift | medium | mitigate | Committed generated output can silently diverge from `src/`. Mitigated by the README rebuild rule added in Task 2 (D-03); enforcement tooling is explicitly out of scope. |
| T-m8f-04 | Tampering | over-broad staging | medium | mitigate | Task 3 stages an explicit path list and asserts the staged set contains nothing outside the build directory, `README.md`, `.gitignore` and `.env.production` — `git add -A` is forbidden. |
</threat_model>
